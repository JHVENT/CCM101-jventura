Mission Reflection

Which cloud infrastructure component do you think is the most important? Why?
For me it's compute. Storage and networking definitely matter, but compute is the piece that actually does something, it's what runs the applications people use. Storage just holds data, networking just moves it around, but compute is where the real work happens. I think that's why cloud providers built their whole business models around renting out compute power in the first place.

How does Linux support cloud computing?
I didn't fully appreciate this before the lab, but Linux is basically the backbone of the cloud. It's free, it's stable, and it doesn't need constant restarts, which matters a lot when you're running thousands of servers at once. The commands I used in this lab, like lscpu and free, are the same tools real cloud engineers use every day, which made the whole thing feel a lot more practical than I expected.

Why is technical documentation important before deploying infrastructure?
Because things break, and when they do, someone needs to understand what was built and why. Without documentation, you're stuck guessing or trying to remember decisions you made weeks ago. I noticed this myself during the lab, when I came back to a step I'd done earlier, having it written down saved me from redoing work I'd already figured out.

What new skills did you learn during this laboratory activity?
I got a lot more comfortable using the Linux terminal to pull real information about a system instead of relying on a graphical interface. I also learned how GitHub handles folders and files through the web browser, including figuring out why some of my files weren't creating folders the way I expected, which took a bit of trial and error to sort out.

How has your GitHub portfolio improved after completing this mission?
It looks a lot more like a real project now. Before, it was just a README with my name on it. Now it has organized folders, actual documentation, and a commit history that shows the work being built step by step, which feels a lot closer to what a professional repository should look like.
